# Page Header — Enverus One

The standard header at the top of every Enverus One page. It carries the page title, a one-line
description, the page-level actions and, on secondary pages, a back button. One structure serves
every page; use it as-is and do not invent per-page variants.

A full page also includes the top navbar across the top and the primary navigation sidebar below it,
to the left of the header and body. When building a whole page, read `navbar.md` and `sidebar.md`
and follow [`rules/page-layout.md`](rules/page-layout.md) for how the pieces fit together.

---

## When to Use

- Every page or view in E1 (Library, Catalog, Inspect, asset detail, etc.) starts with a page header.
- The **back button** is optional and shown only on secondary pages, ones reached from a parent page
  (for example an asset detail opened from the Library). Top-level pages never show it.
- The **action group** is optional too. Omit it entirely when the page has no page-level actions.
- Do **not** use it inside dialogs, drawers, or cards — those have their own headers.
- The **page body** is a sibling of `#page-header`, rendered directly below it. Page content (tabs, tables, cards) never goes inside the header.

---

## Anatomy

```
┌───────────────────────────────────────────────────────────────────┐
│ [‹ Back to Parent]                         (optional back button) │
│ Page Title (h1)                            [Secondary]  [Primary] │
│ Short description of the page.                                    │
└───────────────────────────────────────────────────────────────────┘
```

| Part | Classes | Notes |
|------|---------|-------|
| Outer container `#page-header` | `flex flex-col flex-shrink-0 overflow-hidden` | Always the outermost element. Its children are the optional back row and the title row |
| Back row `#back-button` (optional) | `flex-shrink-0 px-6 pt-4` | Sits above the title; secondary pages only |
| Back button | `variant="outline"` `size="sm"` — `h-8 px-3 text-sm gap-1.5` | Leading `ChevronLeft` icon, label `Back to {parent}`. Border is `--border` in light mode and `dark:border-input` with a `dark:bg-input/30` tint in dark mode (built into the outline variant) |
| Title row `#page-titles` | `flex-shrink-0 px-6 py-4 flex items-start justify-between` | Never shrinks; actions align to the top of the title block |
| Title wrapper `#page-title` | `flex items-center gap-2` | Leaves room for an optional badge/icon beside the title |
| Title `h1` | `text-2xl font-semibold text-foreground` | One `h1` per page |
| Description `p#page-subtitle` | `text-sm text-muted-foreground mt-0.5` | Optional, one short sentence |
| Action group `#page-actions` | `flex items-center gap-2 ml-4 flex-shrink-0` | Optional; omit entirely if there are no actions |
| Secondary button | `variant="secondary"` — `bg-secondary text-secondary-foreground hover:bg-secondary/80`, `h-9 px-4 py-2` | Left of the primary |
| Primary button | `variant="primary"` — `bg-primary text-primary-foreground hover:bg-accent-brand-light`, `h-9 px-4 py-2` | Rightmost action |

Header actions use `size="lg"` (`h-9` in the generated `Button`; its default size is only `h-8`) with `px-4`.
Stock shadcn `Button` has no `primary` variant (only `default`). Add `primary` to the `variant` map in
`@/components/ui/button.tsx` with the classes above; do not use `default` for the page's primary
action or restyle it with `className` (see `shadcn/rules/styling.md`, Post-generation fixes).
| Page body `#page-body` | `flex flex-col flex-1 overflow-hidden` | Sibling of `#page-header`, rendered after it; holds all page content (tabs, tables, cards) |

## Canonical Markup

Button classes are generated by the E1 `Button` component. Prefer the component in React code;
the rendered HTML below is the reference for static mockups and for verifying output. Button
classes match `packages/ui/src/components/ui/button.tsx` in env-one.ui.

### React

Secondary page, with every optional part present. Delete the `#back-button` block for a top-level
page, and delete `#page-actions` if there are no actions.

```tsx
<div id="page-header" className="flex flex-col flex-shrink-0 overflow-hidden">
  {/* optional: secondary pages only */}
  <div id="back-button" className="flex-shrink-0 px-6 pt-4">
    <Button variant="outline" size="sm"><ChevronLeft />Back to Library</Button>
  </div>
  <div id="page-titles" className="flex-shrink-0 px-6 py-4 flex items-start justify-between">
    <div>
      <div id="page-title" className="flex items-center gap-2">
        <h1 className="text-2xl font-semibold text-foreground">Bakken Basin Acreage Blocks</h1>
      </div>
      <p id="page-subtitle" className="text-sm text-muted-foreground mt-0.5">
        Spatial · Enverus DI · Updated Sep 1 · Enverus
      </p>
    </div>
    {/* optional: omit when the page has no actions */}
    <div id="page-actions" className="flex items-center gap-2 ml-4 flex-shrink-0">
      <Button variant="secondary"><Plus />Secondary Action</Button>
      <Button variant="primary"><Plus />Primary Action</Button>
    </div>
  </div>
</div>
```

Top-level page (no back button), with a single primary action:

```tsx
<div id="page-header" className="flex flex-col flex-shrink-0 overflow-hidden">
  <div id="page-titles" className="flex-shrink-0 px-6 py-4 flex items-start justify-between">
    <div>
      <div id="page-title" className="flex items-center gap-2">
        <h1 className="text-2xl font-semibold text-foreground">Flows</h1>
      </div>
      <p id="page-subtitle" className="text-sm text-muted-foreground mt-0.5">
        Run customizable flows to streamline your operations.
      </p>
    </div>
    <div id="page-actions" className="flex items-center gap-2 ml-4 flex-shrink-0">
```

### Header and page body

`#page-header` and `#page-body` are siblings in the page container, in this order. The body holds all
page content and owns its own spacing; the header never wraps it.

```tsx
<div id="page-header" className="flex flex-col flex-shrink-0 overflow-hidden">
  {/* #back-button (optional) and #page-titles, as above */}
</div>
<div id="page-body" className="flex flex-col flex-1 overflow-hidden">
  {/* page content: tabs, tables, cards */}
</div>
```

### Back button rules

- Optional. Show it only when the page has a clear parent; never on top-level pages.
- Label is `Back to {parent page name}` (e.g. "Back to Library"), not just "Back".
- Always `outline` variant, small size (`h-8`), with a leading chevron-left icon. Never primary or secondary.
- It goes above the title, left-aligned, never in the action group.
- It navigates to the parent (route/link), not browser history.

---

## Rules

1. **Structure is fixed.** `#page-header` → ([`#back-button`], `#page-titles` → (title block, [`#page-actions`])). Don't reorder or nest differently.
2. **Title:** sentence-case noun phrase naming the page, not an action. Exactly one `h1`.
3. **Description:** one short sentence, no trailing marketing copy. Drop the `<p>` if it adds nothing.
4. **Actions:** at most one primary, always rightmost. Secondary actions sit to its left.
   More than three actions → move extras into an overflow (`…`) menu.
5. **Icons:** Lucide, leading the label. Inside a `Button` the icon takes the component's default 16px and the default stroke, so add no size classes, `width`/`height` styles or `stroke-width`. Icon-only buttons need an `aria-label`. See `lucide-icons.md` for sizing.
6. **Spacing:** `px-6 py-4` matches the page content gutter. Don't add margin below the header;
   the page body owns its own spacing.
7. **Page body:** a sibling of `#page-header`, rendered after it. Never place page content inside `#page-header`.
8. **Colour:** semantic tokens only (`text-foreground`, `text-muted-foreground`, `bg-secondary`,
   `bg-primary`). No raw hex or palette classes.
9. **Accessibility:** the `h1` is the page landmark title; action buttons must be keyboard reachable
   in visual order (secondary, then primary) and show the `focus-visible` ring.

---

## Full page

A request to build a page always means the whole page: the navbar, the sidebar, the page header and
the page body in one shell. The shell, its markup, scrolling and the page body patterns are defined in
[`rules/page-layout.md`](rules/page-layout.md). Read it and `navbar.md` and `sidebar.md` before writing
the page. This doc defines only the `#page-header` and `#page-body` siblings that sit inside the
shell's main section.

## Checklist

- [ ] `id="page-header"` on the outer container (`flex flex-col flex-shrink-0 overflow-hidden`), wrapping `#page-titles`
- [ ] Back button (`#back-button`) only on secondary pages: outline, `h-8`, chevron-left, `Back to {parent}`, above the title
- [ ] One `h1`, `text-2xl font-semibold text-foreground`
- [ ] Description uses `text-sm text-muted-foreground mt-0.5` (or is omitted)
- [ ] Actions grouped right in `#page-actions`, primary last, ≤ 1 primary (or the group is omitted)
- [ ] Page content is in a sibling `#page-body` (`flex flex-col flex-1 overflow-hidden`) after `#page-header`, not inside the header
- [ ] No hardcoded colours or custom font sizes
